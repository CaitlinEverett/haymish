How it feels

Tidy, without the dread

Haymish works on photos and videos alike. You describe what belongs where; it shows you exactly what it plans to do; you approve. That's the whole loop.

$ haymish ask "file my recipe screenshots into Recipes"
Plan: screenshots matching cooking recipe → album "Recipes".
Opening review — nothing happens until you approve.

Ask in plain language

A local LLM turns your request into a rule, prints its interpretation, and opens a review. haymish find "the whiteboard from the conference" searches your library by meaning, read-only. Add --save and a one-off prompt graduates into standing automation.

Review before anything moves

Every action opens a thumbnail review on localhost. Uncheck the false positives — they're remembered and won't resurface — then Apply. The review uses the same code path as sweep --apply, so what you approve is exactly what runs.

A gentle lifecycle, not a purge

Each rule walks an age-gated ladder — file, then hide, then archive, then stage for deletion. Ages count from the photo's own date, so behavior is predictable: "screenshots older than two weeks leave the roll," full stop. Filed and hidden state syncs everywhere via iCloud Photos.

The AI stays home

haymish index builds a caption and embedding for every photo — all on your Mac via Ollama. Your photos never leave the machine. One exception, and only if you ask for it: individual rules can opt in to the Claude API.

The safety model

Deletion is deliberately hard

This is the identity of the tool, not a footnote. Everything is dry-run by default, every applied action is logged and undoable, and removing a photo for good means passing four gates — in order, every time.

  1. Staged, never automatic

    Scheduled sweeps can only stage deletions — they can never remove anything unattended. Plain-language prompts can't even do that: ask plans are stripped to file, tag, and hide, no matter what's requested.

  2. A verified backup copy exists

    confirm-deletes refuses to proceed unless the original has been archived to your backup volume and the copy is checksum-verified. No backup, no delete.

  3. You confirm, deliberately

    You review the staged photos and type your confirmation. Not a default-accept dialog — an explicit, eyes-open yes from you.

  4. macOS asks one more time

    The final word belongs to a macOS system dialog that cannot be scripted away. Even then, photos land in Recently Deleted with its 30-day window — one last chance to change your mind.

And underneath it all: the Photos library file is never touched directly. Every write goes through Apple's supported automation APIs, and haymish undo reverses the last sweep's album, keyword, and hide actions.

Honest answers

Questions you should ask

Is my library safe?

Yes. Haymish never touches the Photos library file directly — all writes go through Apple's supported automation APIs. Everything is dry-run by default, every applied action is logged, and album, keyword, and hide actions are reversible with haymish undo. Deletion sits behind the four gates above.

Can it delete things by itself?

No. Scheduled sweeps only stage deletions. Nothing is removed until you run confirm-deletes, which requires a checksum-verified backup copy, your typed confirmation, and macOS's own system dialog. Prompts can never delete at all.

Where does the AI run?

On your Mac, via Ollama — captions, embeddings, semantic search, and the planner behind ask all run locally. Your photos never leave the machine. The Claude API is available as a strictly per-rule opt-in; nothing uses it unless you say so in rules.toml.

What about my iPhone?

Haymish runs on your Mac, but its actions — albums, keywords, hidden state — sync everywhere through iCloud Photos. Sweep on the Mac; the calm roll shows up on your phone.

Does it handle videos?

Yes. Rules can target videos and screen recordings directly, the AI index captions each video's poster frame so find and ask see them, and every action — file, hide, archive, delete — works on videos the same as photos.

What does it cost?

Nothing. It's free, and the source is on GitHub.
