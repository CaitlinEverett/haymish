How it feels

Tidy, without the dread

The intended loop is simple: describe or build a collection, inspect the exact candidates and effects, then approve. The first live album/tag canary and cross-device verification are still pending.

Ask in plain language

A local LLM turns your request into a rule, prints its interpretation, and opens a review. haymish find "the whiteboard from the conference" searches your library by meaning, read-only. Add --save and a one-off prompt graduates into standing automation.

Separate organization from cleanup

The starter posture only annotates and adds album views. Hide, backup, and staged cleanup are separate opt-in policies, not synonyms for organization. Final deletion stays disabled until complete Live Photo/RAW manifests and cross-device behavior are verified.

Local by default

haymish index can build local captions and embeddings via Ollama, with explicit coverage and model limits. Photos are not uploaded by default. A rule may opt into a remote provider only when that choice is configured and disclosed.

The safety model

Deletion fails closed

This is the identity of the tool, not a footnote. Ordinary sweeps are dry-run by default and supported additive/state changes use an action ledger. Final deletion is disabled in the current build while its complete backup-manifest gate is implemented.

  1. Staged, never automatic

    Scheduled sweeps can only stage deletions — they can never remove anything unattended. Plain-language prompts can't even do that: ask plans are stripped to file, tag, and hide, no matter what's requested.

  2. A complete backup manifest exists

    A deletion-grade manifest must cover every applicable component, including Live Photo motion and associated RAW files, and every component must be re-verified independently. Legacy single-file archive rows do not qualify, so confirm-deletes currently refuses to proceed.

  3. You confirm, deliberately

    You review the staged photos and type your confirmation. Not a default-accept dialog — an explicit, eyes-open yes from you.

  4. macOS asks one more time

    The final word belongs to a macOS system dialog that cannot be scripted away. Even then, photos land in Recently Deleted with its 30-day window — one last chance to change your mind.

And underneath it all: the Photos library file is never touched directly. Every write goes through Apple's supported automation APIs, and haymish undo reverses the last sweep's album, keyword, and hide actions.

Honest answers

Questions you should ask

Is my library safe?

Safety is the gate, not a claim. Haymish never writes directly to the Photos database; supported mutations go through Apple automation APIs. Automated tests are isolated, final deletion is disabled, and the first real album/tag canary plus verified undo still need live validation before broader trust claims.

Can it delete things by itself?

No. Scheduled work can only stage reviewed candidates, and the current build cannot finalize them at all. Re-enabling confirm-deletes requires complete manifests first; typed confirmation and macOS's own dialog remain additional mandatory gates. Prompts can never finalize deletion.

Where does the AI run?

On your Mac, via Ollama — captions, embeddings, semantic search, and the planner behind ask all run locally. Your photos never leave the machine. The Claude API is available as a strictly per-rule opt-in; nothing uses it unless you say so in rules.toml.

What about my iPhone?

Haymish writes Photos-native albums, keywords, and supported state on the Mac so it does not create a second photo silo. Exact iCloud/iPhone results still need live canary verification and may depend on Apple's sync behavior.

Does it handle videos?

Rules can target videos and screen recordings, and the index can use a local poster-frame derivative. Album/keyword behavior still needs live canary validation; complete backup and deletion parity is not claimed yet.

What does it cost?

Pricing and licensing are not decided. The repository is public but currently unlicensed; private pilots will test a generous trust-floor core plus paid Personal/Studio craft before any launch promise.
